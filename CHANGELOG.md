# PySig 4.2.1

PySig 4.2.1 restores rich movement-level operational outputs while retaining single-intersection optimisation and multi-intersection network functionality.

## Key changes from 4.2

- Restored `results.json` with model, summary, movement, intersection, controller, link, route, assignment and optimisation sections.
- Restored `movement_results.csv`.
- Final optimisation outputs are generated by a fresh assignment/simulation using the selected controller plan.
- Movement outputs include demand, saturation flow, movement capacity, effective green, arrivals, departures, final and maximum queues, queue metres, delay, DoS, unserved demand, storage overflow, full-storage seconds and capacity method.
- `to_lane_id` is now accepted and validated when supplied.
- Retains network links, time-sliced propagation, fixed OD conservation, signal optimisation and pytest tests.

## Run

```bash
python main.py
python main.py validate --config configs/example_intersection_optimisation.yaml
python main.py run --config configs/example_network_optimisation.yaml --output results
python main.py optimise --config configs/example_intersection_optimisation.yaml --output results
pytest -v
```

## Output files

A normal run writes `results.json`, `movement_results.csv`, `route_assignment.csv`, `network_links.csv`, and `assignment_iterations.csv`. Optimisation additionally writes `optimisation_candidates.csv` and `optimisation_summary.json`.

### Important modelling qualification

The 4.2.1 simulation kernel is still time-sliced. Queue and delay results therefore depend on `time_slice_s`, and sensitivity testing at 1, 2 and 5 seconds is recommended before formal use. `warm_up_s` remains a reserved setting and is not yet excluded from reported statistics.

## Version 4.2.2 shared-lane queue kernel

Version 4.2.2 replaces independent movement queues with one physical queue and one storage constraint per `from_lane_id`. Movement demand is retained as subqueue composition within the lane.

- All movements using a lane sum to the lane demand.
- The lane saturation flow is applied once, not once per movement.
- Permitted movements share the lane service capacity.
- Movements with different signal permissions use a simple FIFO blocking factor based on their proportion of the shared queue.
- Lane delay is calculated once from the physical lane queue and partitioned among movement subqueues.
- `results.json` now contains both `lanes` and `movements`.
- `lane_results.csv` is written alongside `movement_results.csv`.

This is a material model change. The FIFO composition rule is a deterministic approximation. Detailed vehicle ordering, overtaking within a wide lane, and access to downstream short-lane pockets remain future refinements.
